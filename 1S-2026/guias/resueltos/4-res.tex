\section*{Funciones de activación}
\subsection*{Ejercicio 3}
La no linealidad es importante porque (1) los datos en el mundo real no suelen ser linealmente separables, (2) permite a la red neuronal que cree barreras de decisión curvas para poder manejar patrones complejos en los datos, y (3) se aseguran que las redes puedan modelar problemas complejos como es el reconocimiento de imágenes.

Si una red neuronal tuviese únicamente funciones de activación lineales, lo que se dará es que la última capa será una combinación lineal de todos los inputs anteriores. Esta red será incapaz de aprender patrones interesantes más allá de los lineales.
\subsection*{Ejercicio 4}
Cuando se entrena una red neuronal, se usa un algoritmo llamado \textit{backpropagation} para calcular cuánto deberían cambiar los pesos de cada neurona para minimizar el error general del modelo. Los ajustes a estos pesos dependen del gradiente de la función de pérdida (error), que esencialmente mide cómo cambia el error a medida que se ajustan los pesos. Pero en redes profundas con muchas capas, estos gradientes pueden volverse muy pequeños (es decir, se ``desvancen'') en ciertas capas, especialmente aquellas lejos de la capa de salida.

Cuando el gradiente se aproxima a cero, los pesos dejan de actualizarse, deteniendo efectivamente el proceso de aprendizaje en esas capas. Este es el problema \textbf{vanishing gradient}, que ralentiza o incluso impide que la red neuronal mejore durante el entrenamiento.

Este problema es común en funciones de activación como la sigmoide o Tanh, porque mapean valores grandes de input a un rango pequeño de output. Como resultado, cuando se calculan los gradientes, tienden a volverse muy chicos, en especial cuando se multiplican a través de muchas capas durante backpropagation.
\subsection*{Ejercicio 5}
Las neuronas con ReLU tienen output cero y derivada cero cuando sus inputs son negativos. Entonces, si los pesos en la red siempre tienden a pasarle un número negativo a una neurona ReLU, esa neurona no va a contribuir al entrenamiento de la red, porque su contribución a las actualizaciones de los pesos que vengan de esa neurona siempre serán cero.

Para solucionar este problema, se pueden usar variaciones de ReLU (Leaky ReLU, PReLU, ELU...) cuya forma permite generar pequeños outputs negativos cuando su input es cero. Esto quiere decir que no hay segmentos de la función que tengan derivada igual a cero.
\subsection*{Ejercicio 6}
Para cualquier vector \(z = [z_{1}, z_{2}, \ldots, z_{n}]\), la función Softmax se define como: $$\sigma(z_{i}) = \frac{\exp(z_{i})}{\sum_{j=1}^{n}\exp(z_j)}$$ donde \(\exp(z_{j})\) es la exponenciación del valor de input, y \(\sum_{j=1}^{n}\exp(z_j)\) es la suma de todos los valores exponenciados para normalizar los outputs. Cada output de \(\sigma(z_{i})\) representa la probabilidad de la clase $i$.

La normalización es clave para que convierta los logits en una distribución probabilística donde la suma de todos ellos dé como resultado 1.

\section*{Forward y backward propagation}
\subsection*{Ejercicio 7}
\textbf{Forward propagation} es el proceso en el cual los datos de input pasan a través de las capas de la red para producir un output. Transforma inputs en predicciones usando pesos, biases y funciones de activación. Preferentemente, el input debe ser normalizado o estandarizado antes de ser procesado por las capas.

\textbf{Backward propagation} es el proceso en el cual se entrena a las redes neuronales para que bajen su error de predicción. Funciona propagando los errores hacia atrás, calculando gradientes usando la regla de la cadena y actualizando los pesos y biases para mejorar el rendimiento.

\section*{Optimización, hiperparámetros y regularización}
\subsection*{Ejercicio 11}
\textit{Batch Gradient Descent (BGD)}:
\begin{itemize}
	\item (+) Entrenamiento estable y robusto.
	\item (+) El algoritmo converge a mínimos.
	\item (-) No es aplicable para un dataset gigantesco. Es computacionalmente inviable.
	\item (-) Un dataset gigante puede tener datos redundantes, así que resulta ineficiente procesar muchos datos iguales.
	\item (-) Puede quedarse atrapado en puntos silla o mínimos locales.
\end{itemize}
\textit{Stochastic Gradient Descent (SGD)}
\begin{itemize}
	\item (+) Menos costoso que BGD.
	\item (+) Converge sin necesidad de procesar todos los datos.
	\item (-) Curva de entrenamiento ruidosa.
\end{itemize}

Se suele preferir \textit{Mini-Batch} porque es computacionalmente viable y tiene una mejor tasa de convergencia en el entrenamiento. Al procesar subconjuntos más chicos de datos, se actualizan los pesos más rápido que en BGD y con menos ruido que SGD. Este algoritmo ofrece un punto medio entre los dos siendo más eficiente y convergiendo a veces más rápido.
\subsection*{Ejercicio 12}
\textit{Momentum} hace que los gradientes ya no sean independientes, sino que se acumulan gradientes de pasos anteriores para que la actualización actual sea una combinación entre el gradiente actual y el anterior. Esto hace que se acelere el aprendizaje, se reduzca el zig-zagueopara que sea una trayectoria más suave, se consiga una convergencia más rápida...

Un \textit{Learning Rate adaptativo} permite que existan algortimos como AdaGrad, RMSprop y ADAM ajustando este parámetro de manera dinámica. Todos estos ayudan a la estabilidad y convergencia del algoritmo de optimización porque se hacen mejores actualizaciones por parámetro.
\subsection*{Ejercicio 13}
\begin{itemize}
	\item \textbf{Step decay}. Cada $n$ épocas el LR se divide por dos.
	\item \textbf{Exponential decay}. Se multiplica constantemente el LR por un valor menor a uno.
	\item \textbf{Cosine Annealing}. El LR sigue una curva de coseno descendente.
	\item \textbf{Reduce on Plateau}. Si la loss function no mejora en varias épocas, se reduce el LR a la mitad.
\end{itemize}
\subsection*{Ejercicio 14}
\emph{(Ejercicio prompteado.)}

Durante el entrenamiento, Dropout desactiva aleatoriamente una fracción $p$ de las neuronas de cada capa en cada paso, forzando a la red a no depender excesivamente de ninguna neurona individual y distribuyendo el aprendizaje de forma más robusta. Esto actúa como regularizador porque impide la co-adaptación de neuronas (que grupos específicos de neuronas memoricen patrones del set de entrenamiento).

Al momento de la inferencia, se necesitan \textbf{todas} las neuronas activas para obtener la mejor predicción posible. Sin embargo, como durante el entrenamiento cada neurona solo estuvo activa una fracción $(1-p)$ del tiempo, sus pesos aprendidos están calibrados para ese régimen reducido. Por eso, al usar todas las neuronas juntas, las activaciones serían más grandes de lo esperado. Para compensar, se \textbf{escalan las salidas} multiplicándolas por $(1-p)$, de modo que la magnitud esperada de las activaciones sea consistente con lo que la red aprendió durante el entrenamiento.

En PyTorch, la instrucción \texttt{modelo.eval()} es crucial porque cambia el comportamiento de la red al modo de evaluación: desactiva el Dropout (todas las neuronas quedan activas con el escaleo correspondiente) y también fija las estadísticas de Batch Normalization (usa la media y varianza acumuladas del entrenamiento en lugar de calcularlas por batch). Si no se llama a \texttt{modelo.eval()}, la red seguiría apagando neuronas al azar durante la inferencia, produciendo predicciones ruidosas e inconsistentes.
\subsection*{Ejercicio 15}
La estandarización de los inputs sirve para allanar el loss landscape y mejora la convergencia. Si no se estandarizan, la convergencia depende directamente de la inicialización de parámetros inicial.

Una capa de batch normalization normaliza los valores de cada batch antes de ciertas capas, corrigiendo el problema de que las capas modifiquen las distribuciones de sus salidas. Es una capa que funciona puramente como regularización.
